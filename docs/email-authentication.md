# メールによるログイン本人確認

一般向けの入口は `/` と `/auth/login`、自治体・組織向けの入口は `/organization/login`。
一般向けの参加カード（セッション参加時も含む）にはメール欄を置かず、
カードの外側・下部に「組織向けログイン」を表示して専用ページに案内する。
専用ページの見出しも「組織向けログイン」。配布済みアカウントのログインなので同意チェックは置かない。
「一般向けログインはこちら」は最初の画面 `/` に戻る。
Google・LINEの既存認証口も表示し、「または」の下にメール・パスワードを置く。
メールログインはメールリンク／PINで毎回本人確認する。Google・LINEの認証フローは変更しない。
メールのリンク先は共通の `/auth/email/verify`。成功後はホームへ移動する。
一般向けの丸いカードは維持する。組織向けは外周余白なしのPC2列・スマホ1列にする。
Google・LINEボタン、メール入力、確認待ちの部品は共通化する。
Figma `48:6133` / `48:6211` の実データに合わせ、見出し28/34px、入力欄48px、SNSボタン56px、送信54px、フォーム343px、PC左右60:40を共通部品へ反映する。
入力欄のOpen Sansはローカル配信。SF ProはApple環境のシステムフォントを使用し、その他のOSはシステムフォントへフォールバックする。
最新のブラウザ目視・フォント実描画の照合は未実施。
このページだけで組織権限は付かない。所属判定・自動組織ログインはAPI側の #319 の別作業。

UIは参考部品の流用であり、パスワードリセットのフローにはしない。
Google / LINE は既存の認証口を維持する。Appleの認証口とパスワードリセットAPIは
ないため、機能しないボタン・リンクは追加しない。

## ローカル

APIリポジトリの `docs/password-email-login.md` に沿ってローカルAPIとMailpit、
検証アカウントを用意し、このリポジトリで `pnpm dev:local` を起動する。
パスワード確認の202応答後はメール確認待ちに留まり、認証済み画面へ移動しない。
同じブラウザでMailpitのリンクを開き、確認ボタンを押して初めてログインする。
リンクを開けない場合は、元のメール確認待ち画面にメールの6桁PINを入力する。
先頭の0も含めて入力する。リンク・PINは15分有効で、どちらかの成功で両方が無効になる。
PINを5回間違えるとリンク・PINを使えなくなり、確認メールの再送が必要になる。
再送は失敗回数をリセットし、旧リンク・PIN・開始Cookieを無効にする。

- API: `EMAIL_VERIFICATION_PAGE_URL=https://localhost:3000/auth/email/verify`
- Web: `https://localhost:3000/organization/login`
- 受信確認: `http://localhost:8025`

パスワード、PIN、確認トークンはURLのクエリ、localStorage、sessionStorageに保存しない。
メールURLのフラグメントは確認画面で読み取り後すぐ消し、自動で本人確認POSTをしない。
ログイン・確認画面ではアクセス解析を読み込まない。再送は60秒間隔で行う。
画面を再読み込みして確認待ちの入力を失った場合は、ログインからやり直す。

## テスト

```sh
pnpm test:auth
pnpm exec tsc -b
```

API応答の検証、再送制限、JSONによる本人確認、Cookie送信、
外部オリジンへのリダイレクト拒否、期限切れ・再利用エラーを検証する。
PINを文字列のJSONで送り先頭0を保持することと、5回制限の429応答も検証する。
ブラウザでデスクトップ・モバイル表示と実際のMailpit受信も確認する。

## デプロイ

ビルドは `CLOUDFLARE_ENV=production pnpm build` のように環境を必ず指定する。
未指定・未知の環境・URL設定の欠落・ローカルURLではビルドを停止する。
`LOCAL_API_URL` は開発サーバー専用で、ビルドには使えない。
本番のWeb/API設定は `https://www.kotohiro.com` にそろえる（メールリンク・Origin・移動先）。

APIの `EMAIL_VERIFICATION_PAGE_URL` は実際のWeb確認画面を指すHTTPS URLにする。
Webの `APP_URL` とAPIの `WEBSITE_URL` は同じオリジンにそろえる。
WebとAPIをセットでリリースする必要がある（旧パスワードログインの200応答から202へ変更）。
組織専用アカウントと自動組織ログインは #319 の別作業。
